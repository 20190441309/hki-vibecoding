## 项目背景

网站骨架建好后，交互还很"素"。我想给它加上高端个人站的那种质感：平滑滚动、页面过渡、磁吸按钮、滚动感知的玻璃拟态导航。这类动效细节多、容易失控，正适合检验 vibe coding 在"品质打磨"阶段的能力。

## 使用 AI 的过程

### 1. 先出设计规划稿，不急着写代码

让 AI 先产出一份完整的《视觉动效设计规划》（存在 `docs/superpowers/specs/`），逐页面列出动效方案、优先级、新增依赖和实施顺序。设计关键词定为：极客（Terminal 元素、等宽字体）、温暖（保留陶土色系）、动感（滚动驱动）、精致（磁力按钮、毛玻璃导航）。

规划稿里明确了一条底线：**保留现有配色体系，动效是加法不是重构。**

### 2. 按依赖关系分三步实现

```
chore: add framer-motion, lenis, gsap dependencies      ← 先装依赖
feat: add SmoothScroll, PageTransition, Magnetic components  ← 再做通用组件
feat: add scroll-aware glass nav, magnetic footer, page transitions  ← 最后接入页面
```

- **Lenis** 负责全站平滑滚动
- **framer-motion** 的 `AnimatePresence` 做路由切换过渡
- **GSAP** 的 `quickTo` + elastic 缓动实现磁吸按钮
- 导航栏监听滚动，超过阈值切换为毛玻璃形态

### 3. 踩坑：格式化工具污染了工作区

某次会话后发现 44 个文件"被修改"，diff 有 8500 行。逐一排查发现：36 个文件只是被转成了 CRLF 行尾，另外 8 个被某个格式化工具改成了另一种风格（tab + 双引号），**没有任何功能变化**。处理方式：全部还原，加 `.gitattributes` 强制 LF，杜绝复发。

## 成果

- 全站平滑滚动 + 路由过渡动画
- 磁吸交互的页脚社交按钮
- 滚动感知的玻璃拟态导航（含移动端汉堡菜单）
- 所有动效遵循统一的缓动曲线 `[0.22, 1, 0.36, 1]`

## 反思

**做得好的**：设计规划稿把"品味"这种模糊的东西变成了可执行的清单，AI 实现时不再瞎发挥。依赖 → 组件 → 接入的三步提交顺序，每一步都可独立验证。

**可以改进的**：AI 工具链自身也会"弄脏"仓库（行尾、格式化风格）。项目一开始就该配好 `.gitattributes` 和格式化规范，而不是出了问题再补。
